# 解密失败（weaver 未启动）与 WiFi 连不上（DHCP）诊断

日期：2026-11-14
类型：分析
状态：已定位，未修复
关联：main `81e7bf2`，日志 `/storage/emulated/0/Download/DLManager/{kernel,recovery}.log`

## 一、解密失败

### 症状

```
skyward: what was entered did not open the user's files:
android.hardware.weaver.IWeaver/default is not running;
the phone's weaver has to be started first
```

密码输两次，两次都是这一句。

### 证据

`ps` 输出（来自 `/mnt/vendor/persist/skyward/diag.txt`）：

```
system  421  qseecomd
root    467  android.hardware.security.keymint-service-qti
root    469  ssgtzd
wifi    557  wpa_supplicant
```

**没有 `android.hardware.weaver`**。

### 判断

不是「密钥服务全挂」——keymint 起来了，qseecomd 也起来了。**只有 weaver 这一个
HAL 没启动**。

Skyward 的解密链要求 weaver 先起，才能验证用户密码；weaver 不在，验证这一步直接
跳过并报错。

### 一个矛盾点

`/mnt/vendor/persist/skyward/decrypt.txt`（52 行）全是同一句：

```
user 0: opened 6e3803381a57a201 (secdiscardable)
```

**文件系统挂载是成功的**（DE 层打开了），而且这条日志反复刷——说明「打开用户文件」
被反复调用，每次都成功，却没人把它标记成完成。

所以现状是：**DE 层通了，CE 层要 weaver 验证，卡在这里**。

### 待查

- manet.toml 里 weaver 的 service 条目是否存在
- weaver 的启动是否被 `when` 条件挡掉（`[[service]] when = {...}`）
- `users()` 是否把 weaver 需要的用户过滤掉了

## 二、WiFi 连不上

### 症状

日志里连了两次，都成功，但拿不到 IP。

### 证据（kernel.log 时间线）

```
06:22:54  Connect with "我是谁的花猪猪"      is SUCCESS   ← 2.4G 连上
06:23:08  locally-generated disconnect ... reason:3      ← 14 秒后自己断开
06:23:08  Connect with "我是谁的花猪猪-5G"  is SUCCESS   ← 切到 5G
06:23:24  DHCP-O RX（收到 offer）
06:23:25  skyward: no address: the DHCP server kept
          taking back the address it offered
```

`reason:3` = `REASON_DEAUTH_NETWORK_LEAVING`，是**本地主动断开**，不是被踢。

### 判断

**根因是 DHCP**，不是关联。关联两次都成功，socket 也在
（`/skyward/run/supplicant/sockets/wlan0`），`wpa_supplicant.conf` 内容正确：

```
network={
	ssid=e5b08fe5928ce5b09a
	psk="wenwen520."
	key_mgmt=WPA-PSK WPA-PSK-SHA256
}
```

DHCP 收到 offer（`DHCP-O`），但后续 ACK 没走通，Skyward 判定「服务器反复收回地址」。

### 次因：2.4G → 5G 的切换

2.4G 本来连上了，14 秒后主动断开去连 5G。如果 5G 的 DHCP 有问题而 2.4G 能用，
**切换策略**可能让原本能用的连接被放弃。

### 可疑的 SELinux 拒绝

```
avc: denied { read write } for comm="wpa_supplicant"
     name="drop_unicast_in_l2_multicast"
```

现在 `permissive=1`，不致命，但这条涉及 wpa_supplicant 的网络配置读写。
DHCP 失败是否与此有关，待验证。

### 待查

- DHCP 客户端是 Skyward 自己实现还是调 `udhcpc`/`dhcpcd`
- ACK 为什么没走通：是包没发出去，还是收到了但解析失败
- 是否可以先不切 5G，用 2.4G 验证 DHCP 本身

## 三、两个问题的关系

**无直接关系**，但都指向同一类问题：**上游新增的 `skyward-programs`（按分区描述
启动程序）可能改变了服务的启动方式**。

`ps` 里 qseecomd、keymint、ssgtzd 都在，说明大部分程序起来了；weaver 不在，说明
它的描述或条件有问题。

## 四、下一步

1. 查 manet.toml 里 weaver 的 service 定义
2. 查 `/mnt/vendor/persist/skyward/diag.txt` 之外的 `dmesg | grep weaver`
3. DHCP：抓一次完整的四步交互（DISCOVER/OFFER/REQUEST/ACK）
4. 考虑关掉 2.4G→5G 自动切换做对照
