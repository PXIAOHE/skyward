### 状态机

```
Idle → Running{done,total} → Done{path,bytes} | Failed(why) | Stopped
                                    ↓ 6 秒（失败 12 秒）

```

### 三个坑

**① DNS 必须用网络的**

```rust
// 错：空列表 → "io: the network gave no DNS server"
skyward_net::http::agent(Arc::new(Mutex::new(Vec::new())))

// 对：用 WLAN worker 从 DHCP 拿到的那份
skyward_net::http::agent(servers)   // ui.rs 里的 servers.clone()
```

**② 卡片高度不一致**

`info_card` 高度由内容行数决定。完成卡片原先显示完整路径（3 行），失败只有 1 行，两者高度差一截。

改法：完成卡片只显示**文件名**，三种结局统一为「标题 + 一行」。

**③ 卡片压住上面的文字**

`footnote` 返回的是**文字最后一行底部**，不是卡片起点。原先手动 `y += caption` 累加，值偏小导致重叠。

改法：直接用返回值 `y = widgets::footnote(...) + m.dp(8.0)`。

### 布局（照抄 pudding 数值）

```rust
let top = m.content_top - m.dp(66.0);                    // 输入框基准
let mut y = field.field.y + field.field.h + m.dp(26.0);  // 按钮
y += m.dp(16.0);                                          // 读 link.txt 那行
```

> 教训：不要自作主张把 `top` 改成 `content_top`——整体下移 66dp 会让输入框、按钮、二维码、状态卡片挤成一团并压到键盘上。

### 工程坑

**`Cargo.lock` 必须同步**

CI 用 `--locked`。新增本地路径依赖要在 lock 里手写条目：

```
[[package]]
name = "qrcodegen"
version = "1.8.0"
```

**没有 `source`、没有 `checksum`**（本地路径包），并在 `skyward-ui` 的 `dependencies` 列表里加 `"qrcodegen"`。

**vendor 的 clippy**

第三方 crate 有自己的风格，在 `lib.rs` 顶部加：

```rust
#![allow(clippy::all, deprecated, unused)]
```

并在其 `Cargo.toml` 补 `edition = "2021"`。

**`mod` 的 cfg 门控**

插 `mod fetch;` 时不要把上一条 `#[cfg(target_os = "android")]` 抢走——`mod filework;` 会在 host 上被编译，连带 `relief`/`skyward_files`/`libc` 全部报错。

## 二、双击亮屏（移植自 pudding v0.2.34）

### 唯一可行的实现

熄屏后**保持显示控制器运行**（只关背光），让触摸屏继续上报；暗屏下两次 `Touch::Down` 落在 600ms、300px 内即视为双击，合成一次电源键按下+抬起，点亮到锁屏。

```rust
} else if app.state.double_tap {
    if surface.is_on() && !keeps_running {
        kmsg("the display is dark; the panel keeps running for the double tap")?;
        keeps_running = true;
    }
} else if surface.is_on() {
    surface.rest()?;          // 原行为
    rested_at = Some(Instant::now());
} else if rested_at.is_some_and(|at| at.elapsed() >= REST) {
    surface.turn_off()?;
}
```

### 为什么不能省电

试过「只写 sysfs + 照常 turn_off」，实测失败。日志证据：

```
14 个触摸全部是 lit true，暗屏期间一个事件都没到 App
kernel.log 里 goodix_ts_report_finger 仍在打，但 evdev 无事件
```

即 `surface.turn_off()` 之后触摸屏**不再向 evdev 投递**，驱动内层有日志但事件出不来。这正是 pudding 注释里那句 *"at rest the touchscreen stops reporting a finger on it"*。

### 开关

设置 → 唤醒 → 双击亮屏（`#[serde(default = "yes")]`，默认开，持久化）。

| 开关 | 熄屏 | 双击 | 耗电 |
|---|---|---|---|
| 开 | 只关背光，面板保持运行 | ✅ | 较高，且不进 suspend |
| 关 | rest → 5 秒后 turn_off | ❌ | 与原版一致 |

### 硬件唤醒键（保留但未生效）

`input.rs` 加了 `KEY_WAKEUP` → `Event::Wake` 的处理，400ms 内重复去重。本机固件不进 gesture 模式，所以这条路径不触发，代码留着。

## 三、装双系统的「安装失败」

**不是 bug**：截图里的 `start /tmp/update-binary: No such file or directory` 来自 `run_script` 路径，即普通刷机 zip（含 `update-binary` 脚本）。

双系统走 `install_system`，完全不碰 `/tmp/update-binary`。选对包时页面会出现「选择空间（8GB / 16GB）+ 滑动以安装」。

顺手加了两条诊断日志（`a335cf7`），下次真遇到脚本包失败可直接定位：

```rust
kmsg("install: {BINARY} written, {copied} bytes, {} there now")   // extract_script 之后
kmsg("install: running {BINARY}, {} bytes")                       // run_binary 之前，附 ensure!
```
