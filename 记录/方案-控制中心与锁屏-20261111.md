# Skyward manet：下拉控制中心、锁屏、解密页对齐

## 一、下拉控制中心（本项目自研，非移植）

从屏幕顶部 40dp 内下拉，滑出一张磨砂玻璃面板。

### 结构

```
crates/skyward-ui/src/app.rs
  ShadeHit            面板上的可点项
  Drag::Shade { start, from }   下拉手势
  App::shade / shade_settle / shade_last / shade_speed / shade_press / shade_hits
  paint_shade()       绘制
  shade_touch()       触摸
  shade_glyph()       各控件的图标
  shade_slider()      两条滑条的取值
```

### 内容

| 元素 | 说明 |
|---|---|
| 时钟 | 44dp，左对齐 |
| 电量 | 右对齐，取自状态栏同一处数据 |
| 磁贴 | WLAN / 截图 / 重启 / 熄屏，2×2，圆角 26dp |
| 亮度条 | 拖动即时改 `state.brightness`（背光跟手） |
| 振动条 | 拖动改 `state.vibration`，与设置页同一个值 |
| 抓手 | 底部 36×5dp 的白条 |

### 图标

三个用现成 glyph：`Icon::Wlan`、`Icon::Restore`（重启）、`Icon::Power`（熄屏）。
相机（截图）、太阳（亮度）、三条竖杠（振动）为**图元自绘**，占空比按 glyph 的约 3/4 对齐。

> 教训：自绘图形若以 `size` 为包围盒直接画，视觉重量和现成 glyph（按 24×24 网格设计）差很多，必须按占空比缩放。第一次相机画到 84% 宽、环形箭头只有 66% 直径，看着明显不齐。

### 磨砂玻璃：三个新画布原语

```rust
Canvas::frost(x, y, w, h, step, tint)      // 降采样 → 两遍盒式模糊 → 双线性放大并着色
Canvas::veil(x, y, w, h, color, cover)     // 逐像素 alpha 混合
Canvas::restore_where(part, x, y, keep)    // 按条件把像素贴回
```

**`fill_rect` 不混合 alpha** —— 它把 RGBA 直接写进缓冲区，而屏幕只读 RGB，所以「黑色 alpha 120」画出来就是纯黑。这是最初「面板下方一片黑」的原因。要半透明必须用 `veil`。

**底部圆角**的做法：先把两个 34dp 角块 `crop` 下来，`frost` 之后再按「圆弧之外」的条件 `restore_where` 贴回原像素。

### 动画

- 拖动 1:1 跟手，拉过 110dp 后有橡皮筋（每多 1dp 只走 0.78dp）
- 松手走真弹簧：`x(t) = (x₀ + (v₀ + ω·x₀)·t)·e^(−ω·t)`，`ω = 2π / 0.62s`
- `v₀` 是手指速度（移动时 0.55/0.45 平滑估计），上限 ±2600 dp/s
- 判定：`shade + speed/1400 ≥ 0.36` 视为展开

> 教训：`motion::Spring` 的「已静止」判据是 `|x| < 0.5`，按**像素**设计的。用它驱动 0~1 的进度时，第一帧就判静止、动画被跳过。归一化的量要自己算缓出或把单位换成 dp。

> 教训：周期 0.34s（ω≈18.5）在 100ms 内走完 80% 行程，30fps 下只有 3 帧，肉眼是瞬移。0.62s 才有过渡感。

### 截图不带面板

`Effect::Screenshot` 原本立即抓 `screen`（已合成的画布），面板在上面。改成**延后一帧**：

```rust
pending_shot = Some(storage);
app.redraw();
// ……合成、present 之后……
if let Some(storage) = pending_shot.take() { save_screenshot(&screen, ...) }
```

主循环里「处理效果」在「合成」之前，所以同一轮就先画了收起面板的画面，再抓。

### 触摸与按键

- 面板打开时所有触摸归面板；面板内按下超过 14dp 视为拖动而非点击（否则从磁贴上起手会把面板拖不动）
- 命中靠 `shade_hits`（绘制时记录），因为叠加层不进页面的 hit 表

## 二、锁屏

面板熄灭再亮起时先显示锁屏：近黑遮罩 + 日期 + 大时钟 + 电量 + 滑动解锁。

- 解锁阈值 96%，松手不到则 0.22s 缓出回位（同样不能用 `Spring`，理由见上）
- 上锁时**只有电源键有效**，触摸、音量键、返回键全部吞掉
- 日期用现成的 `fmt::date(lang, unix, zone)`；时间与电量取自状态栏同一处
- `/metadata` 未挂载时读不到日期，`set_date` 是幂等的，挂上后自然补上

## 三、自动解密（移植自 mariusarva/skyward-pudding）

- 凭据存 `/metadata/skyward/credential`，0600 仅 root
- `/metadata` 平时只读，写入前 `remount_writable(true)`，写完立刻改回
- 选 `/metadata` 而非 persist：**恢复出厂会格式化它**，凭据自动消失
- 三重保护：解不开立刻删并关开关；关开关立刻删；改密码旧凭据自动失效
- **时序坑**（pudding 原版未处理）：UI 首帧时 `/metadata` 尚未挂载，启动时读会读空。真正使用前要**再读一次**

## 四、解密页对齐

### 进度条

固定速率，值按**实测**定：

```
DATA_RATE = 0.000225 /ms  →  4444 ms 填满
实测页面存活             →  4513 ms
```

依据是这行日志（每次页面离开时写）：

```
the decrypt page was up 4513 ms; its bar had reached 98%
```

> 教训：先按 4808 ms 设，切页时只到 94%；再按时间匀速设为 0.00017（5.9s），更差。**必须实测**。
> 教训：日志要在 `tick()` 清零**之前**取值，否则永远读到 0%。

### 返回箭头

`Frame { back: false, ... }` —— 解密页是恢复启动的那一页，后面没有可返回的东西。

### 启动那 4.5 秒

- `wait_prepared()` 从 UI 线程挪进解密线程，否则整个界面卡死、环不动
- 环和条画在**叠加层**（`paint_preparing`），不画进页面帧；页面帧只在阶段变化时 `refresh()` 重建
- 只 `redraw()` 不 `refresh()`：页面帧是缓存的，环画在帧里就永远不动

> 教训：症状是「环不转」，真因常常是**主循环没在跑**（线程被 `wait_prepared` 挡住），而不是绘制参数问题。

## 五、备份修复（同步自 pudding v0.2.33）

- `archive::pack` 返回被跳过的文件数
- `locked(&io::Error)` 判 EPERM/EACCES/ENOKEY（1/13/126），这类文件**计数并跳过**，不再让整个备份失败
- `fs_attributes` 遇到读不到的文件返回默认值
- `[backup] efs` 加入 manet 的基带分区：`modemst1` `modemst2` `fsc` `persist` `bluetooth_a` `bluetooth_b`

根因：我们的 `data.rs` 刻意跳过 user 999（第二空间），其文件留在关闭状态，备份走到那里 `File::open` 返回 ENOKEY，一个文件就把整个备份打断。
