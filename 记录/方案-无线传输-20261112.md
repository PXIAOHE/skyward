# Skyward manet：无线传输（HTTP 文件服务）

把手机里一个文件夹通过 HTTP 服务给局域网内其他设备：浏览器浏览、下载、上传。入口在「高级 → 无线传输」。

## 一、功能

- 服务根目录 = **文件管理器当前所在文件夹**，先在文件管理器进到目标目录，再启动服务
- 端口 **8080**，监听 `0.0.0.0`
- 支持 `GET`（列表/下载）、`HEAD`、`PUT`（上传）、`DELETE`
- 路径保护：`..` 一律拒绝，只能访问所选文件夹
- 单页上限 2 MB 请求头，每请求独立线程

## 三、四个坑

### ① 上传套娃（在 sdcard 里又建 sdcard）

**原因**：上传用相对地址，浏览器基于页面 URL 解析：

```
页面 URL:  http://IP:8080/sdcard/
相对地址:  sdcard/文件.apk
解析结果:  http://IP:8080/sdcard/sdcard/文件.apk
```

**修法**：用绝对地址

```rust
let prefix = if shown.is_empty() {
    "/".to_string()
} else {
    format!("/{}/", url_encode(&shown))
};
// JS: x.open('PUT', '{prefix}' + encodeURIComponent(f.name))
```

### ② 不能下载（点文件 404）

**日志证据**：

```
files: GET /sdcard/                    ← 进入 sdcard
files: GET /粉色冒号vivo sans VF.mtz    ← 少了 sdcard/
```

**原因**：卡片 `href` 只拼了文件名，没带当前目录。根目录下碰巧对，子目录就错。

**修法**：`prefix` 提到循环之前，`href` 拼上它

```rust
let href = format!("{}{}{}", prefix, url_encode(&name), if is_dir { "/" } else { "" });
```

### ③ 符号链接当成不存在

`/sdcard` 是指向 `/storage/self/primary` 的软链接。`Path::is_dir()` 用 `symlink_metadata`，不跟随链接，所以 `/sdcard` 既不是目录也不是文件 → 404。

**修法**：用 `fs::metadata`（跟随链接）

```rust
let meta = fs::metadata(&wanted);
let is_dir = meta.as_ref().map(|m| m.is_dir()).unwrap_or(false);
let is_file = meta.as_ref().map(|m| m.is_file()).unwrap_or(false);
```

### ④ 中文文件名下载失败

`Content-Disposition: attachment; filename="粉色冒号.mtz"` 里直接放非 ASCII，浏览器会拒绝。

**修法**：ASCII 兜底 + RFC 5987 编码

```rust
let plain: String = name.chars().filter(|c| c.is_ascii_graphic() || *c == ' ').collect();
let ascii = if plain == name && !plain.is_empty() { plain } else { "download".to_string() };
let encoded: String = name.bytes().map(|b| {
    if b.is_ascii_alphanumeric() || b"-_.~".contains(&b) { (b as char).to_string() }
    else { format!("%{b:02X}") }
}).collect();

"Content-Disposition: attachment; filename=\"{ascii}\"; filename*=UTF-8''{encoded}"
```

同时按扩展名给正确 MIME（`image/jpeg`、`text/plain` 等），并加 `Accept-Ranges: none`。

## 五、放弃的功能：手机热点

**试过，走不通**。`/vendor/bin/hw/hostapd` 直接运行报：

```
CANNOT LINK EXECUTABLE "/vendor/bin/hw/hostapd":
cannot locate symbol "sk_dup" referenced by "/vendor/bin/hw/hostapd"
```

`sk_dup` 是 OpenSSL 1.1 的 API，Android 用 BoringSSL 没有这个符号。系统的 hostapd 是 **AIDL 服务**（`android.hardware.wifi.hostapd.IHostapd/default`），由 init 拉起，recovery 里没有那个服务。

另外 `wlan0` 作为 STA 连着 Wi-Fi 时不能同时设 AP 地址；`ip link add type __ap` 高通驱动不支持。

**结论**：热点需要 AIDL 环境，recovery 里实现成本极高（5~7 天且成功率低），已删除该模块。

## 六、调试方法

服务端对每个请求打一行日志：

```rust
kmsg(&format!("files: {} {}", request.method, request.path));
```

出问题时：

```sh
dmesg | grep "files:"
```

能看到浏览器实际请求的完整路径，直接判断是路径错、类型判断错还是根本没到。
