# Skyward 双系统包制作（manet / sm8650）

## 一、包的结构

zip，必须含：

| 文件 | 必需 | 说明 |
|---|---|---|
| `system.toml` | ✅ | 清单，**有它就被判为双系统包** |
| `boot.img` | ✅ | 内核镜像（Android boot 格式） |
| `rootfs.img` | ✅ | 根文件系统镜像（ext4 / f2fs / erofs） |
| `init_boot.img` | 可选 | 系统自带首个 ramdisk 时提供 |

### 判定顺序（`skyward-install/src/package.rs:85`）

```
payload.bin 存在        → OTA 更新
system.toml 存在        → 双系统包   ← 优先级高于 update-binary
update-binary 存在      → 脚本包
```

所以在 zip 里放一个 `system.toml`，即使同时带 `update-binary` 也会走双系统路径。

## 二、system.toml

```toml
id         = "ubuntu"
name       = "Ubuntu 24.04"
version    = "24.04.3"
filesystem = "ext4"
init       = "/sbin/init"
minimum    = 8589934592
```

### 校验规则（`skyward-systems/src/package.rs: check()`）

```rust
ensure!(!m.id.is_empty() && m.id.len() <= 32 && m.id.chars().all(id_char), ...);  // a-z 0-9 . - _
ensure!(m.id != "installed", ...);                    // 不能与已装系统同名
ensure!(!m.name.trim().is_empty() && m.name.chars().count() <= 32, ...);
ensure!(m.version.chars().count() <= 32, ...);
ensure!(!m.filesystem.is_empty() && m.filesystem.chars().all(|c| c.is_ascii_lowercase() || c.is_ascii_digit()), ...);
ensure!(m.init.starts_with('/'), ...);                // 必须绝对路径
ensure!(boot > 0 && root > 0, ...);                   // 两个镜像都不能空
```

## 三、制作流程（Ubuntu Base 24.04 arm64 / 8GB）

### 1. 准备工具

```bash
apt-get install -y e2fsprogs zip curl
# mkfs.ext4 / debugfs / resize2fs 在 /usr/sbin，注意 PATH
export PATH=$PATH:/usr/sbin:/sbin
```

### 2. 下载 Ubuntu Base

```bash
cd /workspace/临时/ubuntu
curl -L -o base.tar.gz \
  "https://cdimage.ubuntu.com/ubuntu-base/releases/24.04/release/ubuntu-base-24.04.3-base-arm64.tar.gz"
mkdir -p tree && tar -xzf base.tar.gz -C tree    # 约 105 MB
```

### 3. 定制 rootfs

```bash
# 主机名
echo skyward-ubuntu > tree/etc/hostname
cat > tree/etc/hosts <<'EOF'
127.0.0.1       localhost
127.0.1.1       skyward-ubuntu
::1             localhost ip6-localhost ip6-loopback
EOF

# fstab：root 由 skyward-system-init 挂载，这里只写 tmpfs
cat > tree/etc/fstab <<'EOF'
proc    /proc    proc    defaults              0 0
sysfs   /sys     sysfs   defaults              0 0
devpts  /dev/pts devpts  defaults,gid=5,mode=620,ptmxmode=0666 0 0
tmpfs   /dev/shm tmpfs   defaults,mode=1777    0 0
tmpfs   /run     tmpfs   defaults,mode=755     0 0
tmpfs   /tmp     tmpfs   defaults,mode=1777    0 0
EOF

# 网络 DHCP
mkdir -p tree/etc/systemd/network
cat > tree/etc/systemd/network/20-wired.network <<'EOF'
[Match]
Name=eth0 wlan0

[Network]
DHCP=yes
EOF

# 串口控制台（手机无 HDMI，从电脑看启动）
mkdir -p tree/etc/systemd/system/serial-getty@ttyMSM0.service.d
cat > tree/etc/systemd/system/serial-getty@ttyMSM0.service.d/override.conf <<'EOF'
[Service]
ExecStart=
ExecStart=-/sbin/agetty -o '-p -f -- \\u' --keep-baud 115200,38400,9600 ttyMSM0 vt102
EOF
mkdir -p tree/etc/systemd/system/getty.target.wants
ln -sf /lib/systemd/system/serial-getty@.service \
  tree/etc/systemd/system/getty.target.wants/serial-getty@ttyMSM0.service

# DNS 备用
printf 'nameserver 223.5.5.5\nnameserver 119.29.29.29\n' > tree/etc/resolv.conf
```

### 4. 制作 ext4 镜像

```bash
truncate -s 8G rootfs.img
mkfs.ext4 -F -L skyward-root -d tree rootfs.img
e2fsck -fn rootfs.img        # 校验，应无错
```

**`-d tree` 是关键**：直接把目录树写进新文件系统，不需要 mount loop（容器里可能没权限）。

### 5. 提取 boot.img

从手机当前槽位提取（需 root）：

```bash
cat /dev/block/by-name/boot_a > boot.img     # 96 MB
```

或从原厂 OTA 包里提取。

### 6. 打包

```bash
zip -6 ubuntu-24.04-skyward.zip system.toml boot.img rootfs.img
```

**必须用 deflate 压缩**（默认 `-6`）。8GB 的 ext4 镜像实际只占 150MB，其余是零块，deflate 会压掉 100%。

> 坑：`zip -n .img` 会**关闭压缩**，结果生成 8.1 GB 的包。不要加 `-n`。

结果：**49 MB**。

### 7. 校验

```bash
unzip -l ubuntu-24.04-skyward.zip
unzip -t ubuntu-24.04-skyward.zip | tail -1     # No errors detected
sha256sum ubuntu-24.04-skyward.zip
```

## 四、安装

1. 进 recovery → **安装** → **从内部存储安装**
2. 选 zip
3. **必须出现「选择空间」**（8 GB）——没出现说明 `system.toml` 没被读到，立即停止
4. 滑动确认

装到：

```
rootfs.img  →  data 分区里划出的区域（/data/skyward/systems/<id>.img）
boot.img    →  Skyward 的 store 分区
init_boot   →  store 分区（Skyward 注入自己的程序）
```

**主系统分区完全不写**。

## 五、启动链与失败原因

### Skyward 的注入方式（`skyward-systems/src/install.rs:268`）

```rust
let (init_boot, own_ramdisk) = match contents.init_boot {
    true => {
        // 系统自带 init_boot：保留它的 ramdisk，只在后面追加 skyward/map
        boot::with_start(&own, program, &start)?
    }
    false => {
        // 没有：用手机的 init_boot 头，塞 skyward-system-init 当 init
        boot::init_boot(&fs::read(手机 init_boot), program, &start)?
    }
};
```

### 两条路径

| 包里有 init_boot.img | `init` 是谁 | 适用 |
|---|---|---|
| **有** | 系统自己的 init（Skyward 只追加 `map`） | **另一个安卓系统**（推荐） |
| **没有** | `skyward-system-init` | 通用 Linux（Ubuntu 走这条） |

### 本机实测失败原因

```
boot.img 头版本 4，cmdline 为空，ramdisk_size = 0
```

小米这台是「内核在 boot、ramdisk 在 init_boot + vendor_boot」的结构。原厂内核的 bootconfig 里写死了 Android 启动参数，**不会去挂载我们的 ext4 rootfs**。

`skyward-system-init` 会尝试加载驱动、dm-linear 映射、挂载 rootfs，但它执行的前提是内核已经按正确参数启动。原厂内核不满足。

**结论**：通用 Linux 包用原厂 boot.img 大概率起不来，这是内核限制，不是流程错误。

### 想真正跑起来

需要自己编译内核，开启：

```
CONFIG_EXT4_FS=y
CONFIG_BLK_DEV_DM=y
CONFIG_CMDLINE="root=/dev/dm-0 rootfstype=ext4 init=/sbin/init console=ttyMSM0,115200"
```

然后用这个内核替换 `boot.img`。工作量大（内核源码 + 交叉编译 + 设备树），但这是唯一可行路径。

## 六、安全边界

失败**不会变砖**：

- `skyward-system-init` 出错 → 把原因写进 misc → 自动重启回 recovery
- 启动卡住 → 超时后同样回 recovery
- 主系统分区从未被写

删除：recovery → 双系统 → 删除，空间还给 data。

## 七、另一个安卓系统（成功率更高）

```
android2.zip
├── system.toml          # init = "/system/bin/init"
├── boot.img             # 该 ROM 的内核
├── init_boot.img        # 该 ROM 的 ramdisk（关键！）
└── rootfs.img           # system 分区镜像（ext4/erofs）
```

有 `init_boot.img` 时走「保留系统 ramdisk + 追加 map」路径，安卓自己的 init 会挂载 system/vendor/product，成功率远高于通用 Linux。

**前提**：同机型/同 SoC 的 ROM（内核与驱动要对得上）。
